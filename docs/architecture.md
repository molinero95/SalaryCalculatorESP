# Architecture and incremental DDD refactor

The first refactor separates the simulation session from browser effects. It keeps the static ES-module runtime, persisted JSON, shared URLs, existing fiscal entry points and five-language UI. DDD here means placing rules and use cases in modules with clear dependencies; it does not introduce a framework or class for every value.

| Layer          | Modules                                    | Responsibility                                                                                                                                                       |
| -------------- | ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Domain         | `js/domain/scenario.js`                    | Supported scenario structure, valid scales, type-safe merging and independent ownership of imported arrays                                                           |
| Domain         | `js/domain/housing.js`                     | Housing input fields and the record of which researched housing rules (`js/data/housing-rules.js`) apply to a profile and why each is skipped; changes no amount yet |
| Domain         | `js/domain/payroll-input.js`               | Input bounds, supported options and annual monetary units; independent of HTML/DOM                                                                                   |
| Application    | `js/application/simulation-session.js`     | Restore/import a session, derive the public share payload, select/add/remove tabs while retaining at least one and at most five                                      |
| Infrastructure | `js/infrastructure/session-persistence.js` | Debounce writes to an injected repository and flush before reload/close; timers are injectable                                                                       |
| Presentation   | `js/presentation/payroll-form.js`          | Render form values and translate browser input events into annual amounts; notify the shell when calculations need refreshing                                        |
| Composition    | `js/app.js`                                | Read storage/hash, bind browser events, compose adapters, invoke calculation and coordinate renderers                                                                |

Domain and application modules must not read DOM, storage, URLs or browser lifecycle state, or import infrastructure/presentation modules. Existing pure defaults, region data and fiscal helpers are shared dependencies. The browser shell injects its default language into the session; the application has no dependency on translation or DOM modules. The architectural checks guard browser access and inward dependencies in the new folders, and verify that all browser modules are precached.

## Session boundaries and compatibility

- `createSession(saved, shared)` restores a list or the legacy single `simulation`. An incoming shared simulation becomes the last active tab, retaining up to four local tabs.
- `state.simulation` is a non-enumerable view of the active entry. JSON continues to store `simulations` and `active`; the getter follows replacements during imports.
- `importSession` remains a compatibility API without a file-import UI; it rejects payloads without a simulation object/list before modifying the live session. It retains unspecified personal fields, validates imported values, resets current/scenario defaults as before, and selects the first imported simulation.
- Scenario boundaries drop unknown fields, reject invalid types/nonfinite or negative numbers, and validate both bracket scales. Accepted arrays are cloned so editing one scenario cannot mutate the imported object or another tab.
- Input bounds are explicit domain data. A contract test checks the numeric HTML controls against these bounds. Form changes must update both deliberately.
- `sharePayload` includes only changed current/active scenario parameters. Salary, family details, region and inactive tabs remain excluded from links generated by the app. Handcrafted/legacy incoming payloads retain their previous normalization behavior.
- Automatic session storage and Unicode encoding remain in `js/storage.js`. Manual named-scenario storage and JSON file controls/handlers have been removed; the legacy named-scenario key is left untouched. Browser location/hash clearing, clipboard/file handling and lifecycle registration stay outside application use cases.
- The persistence adapter batches updates and flushes the latest state immediately on `pagehide`. It neither registers listeners nor owns the session.

## Fiscal and presentation modules

`js/tax.js`, `js/calc.js`, `js/defaults.js` and `js/political.js` retain their public imports and pure calculation behavior. They can be reorganized later with compatibility facades if that change helps maintenance. Pension limits now live in `js/domain/pension.js`, and positive foral annual income integration/habitual-rent credits in `js/domain/foral-assessment.js`. These modules remain pure; `calc.js` orchestrates employment and annual contexts without importing UI code.

`js/results.js`, `js/chart.js` and `js/settings.js` remain established renderers. Next extractions are proposal/comparison presentation and browser sharing/import/export adapters from `app.js`, followed by focused settings-editor modules. Each step needs the existing browser/offline regressions and new tests for any extracted rules.
